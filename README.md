## 🧠 What I Care About

### Clean Architecture

I like frontend codebases that are easy to understand, extend, and maintain — with clear separation between UI, state, data fetching, and business logic.

### Type Safety

I use TypeScript to make applications more predictable and reduce the number of bugs that make it to production.

### User Experience

Good software isn't only about functionality. I care about hierarchy, interaction patterns, accessibility, responsiveness, and the small details that make an interface feel polished.

### Performance

I’m interested in building applications that remain fast as they grow — from efficient rendering and data fetching to code splitting and modern Next.js patterns.

### Developer Experience

A good development workflow matters. I value consistent formatting, linting, reusable components, predictable state management, and automated testing.

---

## 🎨 Design Philosophy

My approach sits between **engineering and design**.

I enjoy taking a feature from:

**Research → Wireframes → Design → Implementation → Testing → Iteration**

Rather than treating design and development as separate phases, I try to use engineering constraints to improve the design and design principles to improve the implementation.
